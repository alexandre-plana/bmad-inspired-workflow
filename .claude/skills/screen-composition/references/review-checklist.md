# Checklist de revue

## Tâche
- [ ] La tâche primaire est formulée.
- [ ] Le succès et la décision à prendre sont explicites.
- [ ] Les hypothèses sont séparées des exigences.

## Information
- [ ] Les informations sont classées P0–P4.
- [ ] P0/P1 sont visibles avant l'action qu'elles influencent.
- [ ] Les éléments P4 ont été supprimés ou justifiés.

## Surface
- [ ] Page/panel/modal/inline est justifié.
- [ ] La fréquence, la complexité, le risque et le besoin de contexte parent ont été considérés.
- [ ] Une modal n'est pas utilisée par commodité technique.

## Lecture / actions
- [ ] L'ordre de lecture suit la tâche.
- [ ] L'action primaire est évidente.
- [ ] Les actions secondaires ne concurrencent pas inutilement la primaire.
- [ ] L'action destructive indique clairement sa conséquence.

## Données
- [ ] Chaque chart répond à une question analytique.
- [ ] La table est préférée quand la précision exacte domine.
- [ ] KPI/valeurs disposent du contexte nécessaire.

## États / accessibilité
- [ ] Les états pertinents sont définis.
- [ ] Les erreurs sont placées près de leur cause.
- [ ] Focus, clavier, reflow et alternatives à la couleur sont prévus.
- [ ] Les exigences plus strictes du projet ont été appliquées.

## Handoff
- [ ] Aucun choix de palette/token/lib/composant n'a été inventé contre le design system projet.
- [ ] Les conflits avec une autorité projet sont signalés.
- [ ] Les 3 principales hypothèses/risques maximum sont listés.
